# Replace Organization API

REST API для замены организатора или заказчика в процедурах закупок. Автоматизирует
согласованное обновление связанных записей в нескольких БД за один HTTP-запрос.


## Проблема

При смене организатора или заказчика в закупочной процедуре инженеру приходилось вручную
править данные в нескольких БД и таблицах: `procedures`, `lot`, `lotCustomer`, `contract`,
`catalog_procedure`, `catalog_procedure_lot_customer`, `catalog_contract`. Это долго, легко
ошибиться в одном из полей и легко пропустить одну из таблиц — что приводит к рассинхрону
данных между сервисами (каталог, площадки, контракты).

## Решение

FastAPI-сервис принимает номер процедуры, старый ИНН, новый ИНН и тип замены
(`организатор` или `заказчик`). Дальше автоматически:

1. Находит новую организацию в `section` и связанную запись в `organization`
   по ИНН и типу (`supplier` / `customer`).
2. Находит старую организацию там же — чтобы использовать её ID для точечного обновления.
3. В зависимости от типа замены обновляет связанные таблицы:
   - **Организатор** — `procedures.customerId` в одной из БД площадок
     и поля `placer_*` в `catalog_procedure`.
   - **Заказчик** — `lotCustomer.organizationId`, поля `organization_*`
     в `catalog_procedure_lot_customer`, `customer_*` в `contract`
     и `catalog_contract`.
4. Возвращает JSON-отчёт `updated_tables` — что именно было обновлено и в какой БД.

## Результат

- Ручная правка 5–7 таблиц в нескольких БД → **один HTTP-запрос**
- Исключены ошибки ручного ввода и пропущенные таблицы
- Есть прозрачный отчёт `updated_tables` в ответе — видно, что изменилось
- Один эндпоинт поддерживает оба сценария: организатор и заказчик

## Стек

- Python 3
- FastAPI + Uvicorn
- SQLAlchemy (через внутренний `ConnectionFactory`)
- Работа с несколькими БД одновременно

## Эндпоинты

### `POST /replace-organization`

Заменяет организатора или заказчика в процедуре.

**Query-параметры:**

| Параметр | Тип | Описание |
|---|---|---|
| `Номер_процедуры` | string | Номер процедуры |
| `Старый_ИНН` | string | Текущий ИНН организации |
| `Новый_ИНН` | string | Новый ИНН организации |
| `Тип_замены` | enum | `организатор` или `заказчик` |

**Пример запроса:**

```bash
curl -X POST "http://localhost:8000/replace-organization" \
  -G \
  --data-urlencode "Номер_процедуры=11111111111111" \
  --data-urlencode "Старый_ИНН=1111111111" \
  --data-urlencode "Новый_ИНН=2222222222" \
  --data-urlencode "Тип_замены=организатор"
```

**Пример ответа:**

```json
{
  "success": true,
  "message": "Замена организатор выполнена успешно",
  "procedure_number": "11111111111111",
  "old_inn": "1111111111",
  "new_inn": "2222222222",
  "change_type": "организатор",
  "updated_tables": [
    "44ea21.procedures (id: 12345)",
    "catalog_44.catalog_procedure (id: 67890)"
  ]
}
```

### `GET /`

Возвращает описание API, список эндпоинтов, параметров и примеры запросов.

## Запуск

```bash
git clone git@github.com:username/replace-organization-api.git
cd replace-organization-api
pip install -r requirements.txt

cp config.example.py config.py   # подставь реальные названия БД
python main.py
```

Сервис поднимется на `http://0.0.0.0:8000`.

Swagger-документация: `http://localhost:8000/docs`.

## Обработка ошибок

| Код | Когда возвращается |
|---|---|
| 400 | Не передан один из обязательных параметров |
| 404 | Организация или процедура не найдена в БД |
| 500 | Внутренняя ошибка при обновлении |

Все ошибки возвращаются в стандартном формате FastAPI:

```json
{ "detail": "Нет данных ИНН: 1111111111" }
```

## Примечания

- Использует внутреннюю библиотеку подключения к БД `supp_adel` — в репозитории
  заменена заглушкой, реальные названия БД и хосты вынесены в `config.py`.
- `config.py` не коммитится (см. `.gitignore`). В репозитории лежит
  `config.example.py` с заглушками — скопируй его и подставь свои значения.
- Сервис работает с production-БД — при выкладке в публичный репозиторий креды
  должны задаваться через переменные окружения.
